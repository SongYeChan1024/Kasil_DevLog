# 개인 개발 에이전트 공통 규칙

작성자: 송예찬

Codex와 Claude Code가 함께 사용하는 개인 작업 기준입니다. 공통 규칙의 원본은 블로그 저장소 `tools/agent-rules/COMMON.md`입니다. 프로젝트의 팀 합의·학습 방침·담당 범위는 해당 저장소 지침을 따릅니다.

- 사용자와 한국어로 대화합니다. 진행 안내·질문·승인 요청·결과도 한국어로 쓰고, 기다릴 때는 무엇을 왜 기다리는지 알립니다.
- 시작할 때 대상 폴더, 적용되는 `AGENTS.md`·`CLAUDE.md`, Git 변경 상태를 확인합니다. 추가 문서는 요청과 관련된 부분부터 읽습니다.
- 요청받은 로컬 분석·수정·실행·검증은 완료 기준까지 진행합니다. 이미 허용된 작업과 일상적인 구현 선택마다 다시 승인받지 않습니다. 프로젝트의 직접 학습 순서나 구현 제한을 지킵니다.
- Git push, PR 생성·병합, 배포·게시, 업로드, 외부 문서 변경, 메시지 전송, 비용이 드는 생성은 대상과 내용을 먼저 보여 주고 승인받습니다. 이미 명시적으로 승인받은 대상·내용은 중복 승인 없이 진행합니다.
- 다른 세션의 작업을 보존합니다. 같은 파일을 동시에 고치면 범위를 나누고, 커밋되지 않은 내용을 덮어써야 할 때는 먼저 백업하거나 사용자에게 알립니다.
- 이어서 작업할 때는 변경 상태와 브랜치를 확인한 뒤 `git pull --ff-only`로 최신 상태를 받습니다. 로컬 변경·분기 차이·연결 문제로 실패하면 덮어쓰지 않고 차이와 제한을 확인합니다. 과거 대화보다 최신 인수인계와 현재 코드를 기준으로 판단합니다.
- 가능한 작업은 로컬 CLI와 직접 실행 가능한 스크립트로 처리합니다. 외부 조회와 공식 문서 확인은 작업에 필요할 때 진행합니다.
- 비밀번호·API 키·토큰을 채팅·로그·Git에 노출하지 않습니다. 인증정보가 들어갈 수 있는 설정·환경 변수·원격 주소는 필요한 항목만 읽고, 출력 전에 민감한 값을 제외합니다.
- 검증은 변경의 영향과 프로젝트 기준에 맞춥니다. 관련 검사에서 실패하면 원인을 고치고 필요한 검사를 다시 실행합니다. 문구 수정마다 전체 빌드·전체 테스트를 반복하지 않습니다.
- 설정 파일의 존재, 실제 연결·실행 성공, 결과 검증을 구분합니다. 실제 실행한 명령과 결과, 확인하지 못한 항목을 밝히며 성공을 추정해 보고하지 않습니다.
- 설계 대안에는 근거를 설명하고 제안·확정·미검증 상태를 구분합니다. 정해지지 않은 수치나 기능을 임의로 확정하지 않습니다.
- 문서·변경 기록·Revision History의 작성자는 송예찬으로, 팀 프로젝트는 요청한 팀원으로 적습니다. 작성자 칸에 AI나 도구 이름을 적지 않습니다.
- 작업을 마칠 때 필요한 인수인계 문서를 갱신합니다. 공개 기록은 블로그, 비공개 원문은 노션에 두며 각 저장소의 공개 범위를 따릅니다.
- 공통 규칙은 이 원본에서 고치고 동기화합니다. 프로젝트 지침에는 고유한 제약·검증 명령·자주 틀리는 함정을 남깁니다. 작업 이력은 인수인계 문서에, 재사용할 절차는 필요할 때 스킬·스크립트에 둡니다.
