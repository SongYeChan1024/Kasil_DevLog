노션의 프로젝트 소개와 GitHub 자료를 한곳에서 볼 수 있는 개인 포트폴리오를 구성함.
별도의 프레임워크 없이 HTML·CSS·JavaScript로 만들고 GitHub Pages에서 제공하는 구조임.

[포트폴리오 열기](https://songyechan1024.github.io/)

## 첫 화면과 연표 연결

화면의 중심은 프로필에서 이어지는 세로 타임라인임.
현재 개인 이력과 일곱 프로젝트를 포함해 14개 항목을 배치함.

| 구간 | 구성 |
| --- | --- |
| 로딩 | 약 5초, 카실 캐릭터 달리기, 로딩 바 |
| 프로필 진입 | 로딩 페이드 아웃 후 프로필 줌인 |
| PLAYER STATUS | 프로필과 다섯 칸의 Skills, 근거를 여는 상세창 |
| 스크롤 전환 | 사진 프레임이 연표 시작점으로 이동하고 캐릭터로 전환 |
| 타임라인 | 학업·경력·교육·프로젝트를 시간순으로 배치 |
| 프로젝트 선택 | 둥근 Click! 말풍선, 개요·담당 역할·자료를 보여 주는 상세창 |

로딩 생략과 인트로 다시 보기 버튼은 제거함.
연표 문구는 `My TimeLine`, `나의 타임라인`으로 맞춤.
프로젝트마다 팀 전체 결과와 개인 담당 범위를 나누어 적음.

콘텐츠는 `content.js`, 화면 동작은 `app.js`, 표현은 `styles.css`로 나눔.
프로젝트 소개나 자료 링크를 바꿀 때 화면 코드를 함께 고칠 필요를 줄이기 위한 구성임.

## 캐릭터의 방향과 동작 수정

로딩과 타임라인에서 같은 카실 캐릭터를 사용함.
화면 아래로 이동하는 흐름에 맞춰 정면을 향하도록 구성함.

걷기와 달리기는 각각 8프레임 시트를 사용하고 좌우 발이 번갈아 나오도록 수정함.
스크롤 속도에 따라 움직임을 바꾸며, 지점을 넘을 때는 준비·공중 자세·착지를 구분함.
걷기와 점프에 서로 다르게 남아 있던 연두색 테두리도 제거함.

프로필 사진이 먼저 연표에 도착하고 캐릭터로 바뀐 뒤 출발하도록 순서를 맞춤.
프로젝트 상세창을 열면 이동 캐릭터를 숨기고,
운영체제의 모션 감소 설정에서는 이동 애니메이션을 생략함.

## 경력과 자료 정리

학교 이름을 부산중앙고등학교로 바로잡음.
코인트 서비스는 이력서에서 재직 기간을 확인해 5년 이상 근무한 경력을 반영함.
ERGOSQUARE: ARCHITECT는 엘리스 수료 후 시작한 개인 프로젝트이므로 NCAI 앞에 배치함.

Skills에는 Unity, C#, Git, Notion, Blender를 넣음.
각 항목에서 프로젝트 경험과 다음에 보완할 범위를 확인할 수 있게 함.
Blender에는 NCAI 수업 결과 이미지 두 장과 원문 링크를 연결함.

프로젝트 자료는 빌드와 기획서를 구분함.
DarkDock의 개인 설계 자료, 모자이크의 팀 공통 기획서,
Pet Bloom Garden 기획서와 ERGO의 이전 원안을 각각 표시함.
이전 원안을 현재 기획서로 소개하거나 팀 기획서를 개인 단독 작성물로 표시하지 않음.

큰 게임 빌드는 Google Drive에서 내려받고 사이트는 링크만 제공하는 방식으로 정함.

## 모자이크 Windows 재빌드

기존 실행 파일을 찾는 데 그치지 않고 공개 저장소의 소스에서 Windows x64 빌드를 다시 만듦.

| 항목 | 기준과 결과 |
| --- | --- |
| 소스 | `WooSeonghyeok/UnityProject_mozAIc`, `db2a2dd` |
| Unity | 2022.3.62f3 |
| 씬 | 기존 활성 씬 13개 |
| 결과 | 빌드 종료 코드 0, 성공 기록 확인 |
| 배포용 ZIP | 약 822 MiB, 실행에 필요한 253개 파일 |
| 압축 검증 | ZIP 전체 무결성 검사 통과 |
| 게임 확인 | 직접 테스트 플레이 완료, Helpy AI 연결 불가 확인 |

소스 코드는 수정하지 않음.
에디터가 반입 과정에서 다시 저장한 설정은 변경 내용을 보관한 뒤 원래 상태로 복원함.
배포용 ZIP에서는 디버그 정보와 작업 로그, 저장 데이터 백업을 제외함.

그래픽 장치 없이 실행한 빌드 로그에는 GI 알베도 렌더링 관련 오류 메시지가 남았음.
최종 빌드는 성공했지만, 이를 오류 메시지가 전혀 없었던 빌드로 기록하지는 않음.

Helpy AI 패키지를 받아 빌드할 수 있는 것과 서비스에 연결되는 것은 별개였음.
현재 AI 대화는 사용할 수 없으므로 상세 화면에 그 사실을 표시함.
개발 당시의 동작은 플레이 영상으로 확인할 수 있게 연결함.

## 검증한 범위

JavaScript 구문과 콘텐츠 구조, 로컬 파일 경로, HTML 앵커, 자료 링크 형식을 검사함.
모션 검사에서는 실제 동작 함수를 실행해 전환 순서와 프레임 순환을 확인함.
좌표와 DOM을 대신한 검사이므로 실제 브라우저 화면 검수와는 구분함.

데스크톱에서는 작업 중 로딩·연표·점프·상태창을 확인함.
최종 수정본의 모바일 화면과 모든 Skills 상세창을 실제 브라우저에서 다시 검수한 상태는 아님.
게임의 직접 테스트 플레이 결과도 웹사이트의 모든 화면을 검사한 결과로 합치지 않음.

## 후속 작업 — After Seconds 에셋 조사

오늘은 포트폴리오 마무리까지 진행하고 에셋 조사는 보류함.

- 실제 씬에서 사용하는 메시의 삼각형 수, 배치 수, LOD와 재질을 조사할 것.
- 그림자·카메라·컬링 조건을 맞춘 실제 플레이 구간에서 기준 수치를 다시 측정할 것.
- 프랍을 일괄적으로 같은 폴리곤 수로 줄이기 전에 크기·화면 점유·실루엣을 기준으로 구분할 것.
- 원본을 보존한 뒤 대표 에셋부터 조정하고 같은 시점의 화질과 성능을 비교할 것.

예정된 분업은 Codex의 사용 현황·수치 조사와 Claude의 예산·디테일 검토임.
결과를 합친 뒤 실제 Unity 검수는 순서대로 진행할 예정이며, 오늘 조사를 시작하거나 메시를 변경하지는 않음.
