11월 20일 밤부터 21일 새벽까지 이어서 작업함.
오늘은 에이전트를 더 잘 쓰려고 가져온 지침을 정리하는 데서 시작했음.

내가 걱정했던 건 에이전트에게 시킬 행동과 팀원끼리 지킬 협업 규칙이 섞이는 부분이었음.
문장을 한곳에 모아 두면 찾기는 쉬워지는데, 누가 정한 규칙이고 누구에게 적용되는지까지 같은 의미가 되는 건 아니었음.

## 어느 문서가 원본인지부터 정리함

개인 지침에는 에이전트가 요청을 읽고, 수정 범위를 정하고, 검증하고 보고하는 방법을 둠.
팀 합의와 게임 명세는 각각의 기존 문서에서 관리하도록 함.

개인 지침에서는 그 원문을 찾아 읽고 따르도록 연결함.
원문을 길게 복제해 놓으면 한쪽만 바뀌었을 때 어느 쪽을 따라야 하는지 다시 헷갈릴 수 있음.

생성 도구가 사람용 문서를 안내문으로 바꾼 부분도 원문으로 복원함.
앞으로는 그런 문서를 생성 대상에서 빼도록 고침.
설치 과정에서 작업 브랜치를 자동으로 바꾸거나, 수동 수정한 지침을 기본 옵션으로 덮어쓰던 동작도 정리함.

이때 완료의 의미도 나눠 둠.
AI 검토를 마친 것, 담당자가 승인한 것, 자동 검사를 통과한 것, 실제 게임에서 동작을 확인한 것은 각각 기록할 내용이 다름.

## 최신 파일을 받는 것부터 확인할 게 있었음

원격 커밋을 받으려니 로컬에서 고친 지침과 겹치는 파일이 있었음.
기존 변경을 백업하고, 원격 내용과 수정 전 기준본을 비교해서 충돌을 해결함.
최신 커밋을 받은 뒤에도 내가 수정해 둔 내용이 남아 있는지 확인함.

애프터 세컨즈는 로컬이 원격보다 16개 커밋 뒤에 있었음.
최신 코드를 받고 보니 오래된 이어하기에 미완료로 적힌 교환·경비·층 이동이 이미 연결돼 있었음.

인수인계를 읽는 것만으로 끝내면 같은 일을 다시 시킬 수도 있겠다는 생각이 듦.
다음 작업은 문서 날짜와 현재 코드를 같이 봐야 했음.

## 두 세션에 맡길 파일을 먼저 나눔

열려 있던 두 세션에 애프터 세컨즈 작업을 나눠 맡김.
한쪽은 위치 교환 예약 순서를, 다른 쪽은 층 이동 실패와 CCTV 보고를 맡음.
Unity 실행과 최종 검수는 한곳에서 진행하도록 함.

같은 폴더에서 작업하더라도 수정할 파일을 정해 두니 결과를 비교하기 쉬웠음.
작업마다 어떤 현상이 잘못됐는지, 수정 전에도 재현되는지, 무엇을 확인하면 끝났다고 할지를 붙여 둠.

이번에는 대기 중인 교환의 순서, 실패한 승강기 이동 뒤 남아야 할 예약, 늦게 온 관측 정보에서 문제가 나옴.
기능 하나씩 볼 때보다 기다리거나 실패한 뒤 이어지는 상태를 같이 보니 확인할 지점이 더 구체적이었음.

## 검사 숫자 옆에 실행한 환경을 적음

실제 게임 C# 소스를 검사에 넣어도 씬이나 충돌을 대신하는 간단한 객체를 썼다면, 그 결과가 확인하는 범위는 거기까지임.
그래서 독립 코드 검사와 실제 Unity 검수를 나눠 기록함.

Unity에서는 B5가 로드되고, 배식과 첫 교환이 끝나고, 입력이 돌아오는 것까지 확인함.
그렇다고 승강기 도착 지점을 막아 직접 왕복해 본 것이나 전체 층을 완주한 것까지 완료로 적지는 않음.

다음에도 분업할 때는 수정할 파일과 완료 조건을 먼저 붙여 둘 생각임.
결과를 받을 때는 통과 개수와 함께 **어떤 환경에서 무엇을 확인했는지**부터 볼 것.
