## GameStart 버튼은 어느 씬을 여나

빌드 설정의 첫 씬은 `TitleScene`, 다음은 `GameScene`임. `UI_Title`은 자식 버튼을 찾아 두고, `Start()`에서 `ChangeScene`을 클릭 이벤트로 넘김. 버튼은 받은 함수를 `onClick.AddListener`로 등록함.

실제 클릭이 들어오면 그때 `SceneManager.LoadScene("GameScene")`이 실행됨. 버튼 쪽은 다음 씬 이름을 몰라도 되고, 어느 씬으로 갈지는 타이틀 스크립트 한 곳에서 보면 됨.

## 발사음과 명중 효과가 나오는 순간이 다름

| 시점 | 코드에서 일어나는 일 |
| --- | --- |

| 적이 피해를 받음 | `Enemy.TakeDamage()`에서 체력을 줄이고 피격음을 재생함. 체력이 0 이하면 처치 점수를 전달함 |

적의 시작 체력은 100이라 같은 적에 20씩 다섯 번 맞으면 처치 조건에 들어감. 벽처럼 `IDamageable`이 없는 곳에 닿아도 탄은 사라짐. 이 경우에는 명중 효과를 만드는 코드까지 들어가지 않음.

## 열 번째 처치가 클리어 화면으로 이어지는 과정

어제 남은 문제는 **이번에 받은 10점**과 **지금까지 쌓인 총점**을 구분하는 것이었음. 오늘 파일의 `AddScore`를 보면 두 값이 쓰이는 위치가 보임.

```csharp
this.score += score;
uiManager.UpdateScoreUI(this.score);

if (this.score >= 100)
{
    Cleargame();
}
```

90점에서 한 마리를 잡으면 매개변수 `score`는 10이고, 더한 뒤의 `this.score`는 100임. UI에는 100을 보내서 `Score: 100`을 표시하고, 같은 누적값으로 클리어를 판정함. 적이 점수 텍스트나 클리어 패널을 직접 찾아갈 필요가 없음.

## 체력이 정확히 0이면 어떻게 되나

게임 시작 때 `UIManager.Init()`이 클리어·게임오버 패널을 숨김. 이후 점수가 100 이상이면 클리어 패널을, 플레이어 사망 콜백이 오면 게임오버 패널을 켬. 양쪽 다 `Time.timeScale = 0f`로 물리와 게임 시간의 진행을 멈춤.

현재 코드에는 경계값 차이가 남아 있음. 적은 `hp <= 0f`에서 죽고 플레이어는 `hp < 0f`에서 사망 콜백을 보냄. 체력 100인 플레이어가 피해 10을 열 번 받으면 정확히 0이라 아직 게임오버가 뜨지 않고, 한 번 더 받으면 조건에 들어감. 다음에 체력 규칙을 정할 때 볼 부분임.
