오늘은 어제 과제였던 성적 처리기 풀이부터 보고 → 2중 반복문 연습 → 함수(Function)까지 넘어감

## Chapter 01. 과제 1 성적 처리기 풀이

### 수업 풀이

```csharp
int myScore = 100;
char myGrade = ' ';
bool isMultiplesOf4 = false;

if (myScore >= 0 && myScore <= 100)
{
    if (myScore > 95) { myGrade = 'A'; }
    else if (myScore > 90) { myGrade = 'B'; }
    else if (myScore > 85) { myGrade = 'C'; }
    else if (myScore > 80) { myGrade = 'D'; }
    else { myGrade = 'F'; }

    if (myScore % 4 == 0)
    {
        isMultiplesOf4 = true;
    }
    else
    {
        isMultiplesOf4 = false;
    }
    // 학점과 4의 배수 여부 출력
}
else
{
    Debug.Log("점수는 0~100점 사이의 값만 입력 가능합니다.");
}
```

풀이 순서를 주석으로 먼저 나눠 둠

1. 받은 점수를 기준으로 등급을 매기는 기능
   - 점수 정보 → 등급 기준 → 등급을 저장할 공간
2. 받은 점수가 4의 배수인지 판별하는 기능

어제 짰던 “방법 1. if - else if”와 거의 같은 구조\
위에서부터 검사해서 처음 true 하나만 실행하니까 아래 범위만 적어도 됨

### 내 풀이와 비교

| | 내 풀이 | 수업 풀이 |
| --- | --- | --- |
| 학점 나누기 | `switch ((score - 1) / 5)` | if - else if |
| 학점 자료형 | `string grade = "F"` | `char myGrade = ' '` |
| 범위 밖 점수 | 처리 안 함 (101점도 F) | 바깥 if로 막고 안내 문구 출력 |
| 4의 배수 | 출력할 때 바로 `%` 검사 | bool 변수에 먼저 담아 둠 |

어제 정리 끝에 “101점이나 -5점을 넣으면 지금은 F로 나옴”이라고 적어 뒀는데\
수업 풀이는 처음부터 0~100점일 때만 계산하도록 감쌈\
과제 전제가 0~100점이어도 이상한 값이 들어올 수 있다고 보고 막아 두는 쪽

학점이 한 글자라 `char`를 쓴 것도 차이\
`'A'`처럼 작은따옴표 한 글자로 저장함

### bool 대입은 더 줄일 수 있을 듯

```csharp
if (myScore % 4 == 0)
{
    isMultiplesOf4 = true;
}
else
{
    isMultiplesOf4 = false;
}
```

`myScore % 4 == 0` 자체가 이미 true/false를 돌려주는 식임\
그래서 아래 한 줄로 써도 같은 값이 들어감

```csharp
isMultiplesOf4 = (myScore % 4 == 0);
```

실제로 뒤에서 함수로 바꾼 `IsMultipleOf4`는 이렇게 씀\
출력할 때도 `if (isMultiplesOf4 == true)`보다 `if (isMultiplesOf4)`면 충분하고, 반대쪽은 `else if (== false)` 대신 else 하나면 됨

## Chapter 02. 2중 반복문

### 반복문 안에 반복문

```csharp
for (int i = 0; i < 3; ++i)
{
    for (int j = 0; j < 5; ++j)
    {
        Debug.Log("i의 값 : " + i + ", j의 값 : " + j);
    }
}
```

| i | 안쪽에서 j가 도는 값 | 출력 수 |
| ---: | --- | ---: |
| 0 | 0, 1, 2, 3, 4 | 5 |
| 1 | 0, 1, 2, 3, 4 | 5 |
| 2 | 0, 1, 2, 3, 4 | 5 |

바깥 i가 한 번 돌 때 안쪽 j는 처음부터 끝까지 다 돎\
그래서 출력은 `3 × 5 = 15`줄

### 안쪽 변수 이름을 j로 쓰는 이유

`for` 괄호 안에서 선언한 `int i`는 반복문이 끝날 때까지 살아 있음\
지역변수 개념이라 그 안쪽 블록에서도 i가 그대로 보임

그래서 안쪽 반복문에서 i를 또 선언할 수 없고 다른 이름인 j를 씀\
반대로 바깥 for가 끝나면 i는 사라져서 다음 for에서 `int i`를 다시 선언할 수 있음\
오늘 파일에서도 for마다 `int i`를 새로 선언함

### 구구단

```csharp
for (int i = 1; i <= 9; ++i)
{
    for (int j = 1; j <= 9; ++j)
    {
        Debug.Log(i + " X " + j + " = " + (i * j));
    }
}
// 1 X 1 = 1 ... 9 X 9 = 81
```

바깥 i가 단, 안쪽 j가 곱하는 수\
1단부터 9단까지 `9 × 9 = 81`줄이 나옴

`(i * j)`를 괄호로 감싼 부분\
`*`는 `+`보다 먼저 계산돼서 이 식은 괄호가 없어도 결과가 같음\
대신 `i + j`처럼 `+`로 계산하는 경우는 앞의 문자열과 먼저 이어 붙어서 `"1" + "1"` → `11`처럼 나옴\
문자열 연결 중간의 계산은 괄호로 감싸 두는 게 안전할 듯

### 별 피라미드

```csharp
for (int i = 1; i <= 5; ++i)
{
    string stars = "";
    for (int j = 1; j <= i; ++j)
    {
        stars += "*";
    }
    Debug.Log(stars);
}
```

```text
*
**
***
****
*****
```

구구단과 다른 점은 안쪽 조건이 `j <= i`라는 것\
안쪽 반복 횟수가 고정이 아니라 바깥 i에 따라 1, 2, 3, 4, 5번으로 늘어남

`stars`를 바깥 for 안에서 선언해서 줄마다 빈 문자열로 다시 시작함\
안쪽에서 `+=`로 별을 붙이고 다 붙인 뒤 한 번만 출력\
`Debug.Log`를 안쪽에 넣으면 별이 한 개씩 따로 찍히니까 출력 위치가 중요함

## Chapter 03. 지뢰찾기

### 문제

```text
가로 6칸, 세로 5칸 지뢰판
14번째, 19번째, 28번째 칸에 지뢰가 있음
[] [] [] [] [] []
[] [] [] [] [] []
[] [X] [] [] [] []
[X] [] [] [] [] []
[] [] [] [X] [] []

지뢰 3개를 모두 발견하면 게임 중단
매 칸 확인할 때마다 'XX칸 확인중..' 출력
지뢰를 찾을 때마다 'XX칸에 있는 지뢰 제거' 출력
```

### 수업 코드

```csharp
for (int i = 1; i <= 30; ++i)
{
    Debug.Log(i + "칸 확인중..");
    if (i == 14 || i == 19 || i == 28)
    {
        Debug.Log(i + "칸에 있는 지뢰 제거");
    }
}
Debug.Log("게임 종료");
```

6 × 5 = 30칸을 1번부터 하나씩 확인\
지뢰 칸 3개는 어제 배운 `||`로 묶음

### 칸 번호와 그림 위치 맞춰 보기

수업 외로 그림 위치랑 칸 번호가 맞는지 확인해 봄\
가로가 6칸이니 `(번호 - 1) / 6`이 몇 번째 줄, `(번호 - 1) % 6`이 몇 번째 칸

| 칸 번호 | (번호 - 1) / 6 + 1 | (번호 - 1) % 6 + 1 | 그림 |
| ---: | ---: | ---: | --- |
| 14 | 3줄 | 2번째 | 3줄 2번째 X |
| 19 | 4줄 | 1번째 | 4줄 1번째 X |
| 28 | 5줄 | 4번째 | 5줄 4번째 X |

그림이랑 정확히 맞음\
어제 성적 처리기에서 쓴 정수 나눗셈 `- 1` 트릭이 여기서도 똑같이 나옴

### 3개 다 찾으면 멈추기

문제에는 “지뢰 3개를 모두 발견하면 게임 중단”이라고 되어 있음\
그런데 수업 코드는 28칸에서 마지막 지뢰를 찾고도 29, 30칸까지 확인하고 끝남

```text
28칸 확인중..
28칸에 있는 지뢰 제거
29칸 확인중..
30칸 확인중..
게임 종료
```

어제 배운 `break`를 쓰면 바로 멈출 수 있음\
찾은 지뢰 수를 세다가 3개가 되면 빠져나가기

```csharp
int foundMineCount = 0;

for (int i = 1; i <= 30; ++i)
{
    Debug.Log(i + "칸 확인중..");
    if (i == 14 || i == 19 || i == 28)
    {
        Debug.Log(i + "칸에 있는 지뢰 제거");
        ++foundMineCount;

        if (foundMineCount == 3)
        {
            break;
        }
    }
}
Debug.Log("게임 종료");
```

```text
28칸 확인중..
28칸에 있는 지뢰 제거
게임 종료
```

`if (i == 28) break;`로 써도 지금은 같은 결과\
그래도 지뢰 위치가 바뀌면 그 숫자도 같이 고쳐야 해서 개수로 세는 쪽이 문제 문장이랑 더 맞아 보임

## Chapter 04. 함수(Function)

### 함수 = 기능 하나

프로그램은 100% 기능 단위로 이루어져 있음\
그 기능을 프로그래밍 용어로 **함수**라고 부름

함수는 입력을 받아서 어떤 행동을 하고 출력을 내보내는 것\
11월 4일 첫 수업에서 본 컴퓨터의 `입력 → 처리 → 출력` 흐름을 코드 안에서 작게 만드는 느낌

| 구성 요소 | 의미 |
| --- | --- |
| 입력(Input) | 함수가 받는 값 |
| 행동(Behavior) | 함수가 하는 일 |
| 출력(Output) | 행동의 결과 |
| 함수의 이름(Function Name) | 부를 때 쓰는 이름 |
| 출력의 타입 | 결과의 자료형 |

```csharp
출력의타입 함수의이름(입력)
{
    // 함수가 하는 행동
    // 행동의 결과를 출력
}
```

수업 파일은 이 개념 주석을 `#region` ~ `#endregion`으로 감싸 둠\
Visual Studio에서 그 구간을 접었다 펼 수 있어서 긴 메모를 정리할 때 편함

### 더하기 함수 Plus

```csharp
int Plus(int lhs, int rhs)
{
    int result = lhs + rhs;
    return result;
}
```

| 구성 요소 | Plus |
| --- | --- |
| 입력 | `int`, `int` |
| 행동 | `int + int` |
| 출력 | 더한 결과값 |
| 이름 | `Plus` |
| 출력 타입 | `int` |

`return`이 결과를 함수 밖으로 내보내는 부분\
`lhs`, `rhs`는 왼쪽(left-hand side)·오른쪽(right-hand side) 값이라는 뜻의 이름

```csharp
int result = Plus(10, 20);
Debug.Log("result 는 :" + result); // result 는 :30
```

사용할 때는 `함수명(넣어야 할 입력)`\
10이 lhs, 20이 rhs로 들어가고 return한 30이 result에 저장됨

함수는 Start 밖, 클래스 안에 만들어 두고 Start에서 불러 씀\
Start 안의 result와 Plus 안의 result는 이름만 같고 서로 다른 지역변수임

### 문자를 숫자로 GetNumberFromChar

```csharp
int GetNumberFromChar(char c)
{
    int result = (int)c; // 명시적 형변환
    return result;
}

int b = GetNumberFromChar('a');
Debug.Log(b); // 97
```

11월 4일에 본 명시적 형변환 `(int)` 그대로\
입력 자료형은 `char`, 출력 자료형은 `int`로 서로 달라도 됨

### 출력이 없는 함수 PrintHello

```csharp
Debug.Log("-----------------");
Debug.Log("안녕하세요 용사님!");
Debug.Log("-----------------");
Debug.Log("저는 용사님을 도와드릴 NPC 라고 해요.");
Debug.Log("-----------------");
```

정해진 양식에 맞춰 출력해야 하는 경우\
플레이어마다 이걸 매번 적으면 어제 반복문 앞에서 본 것처럼 관리 포인트가 늘어남

```csharp
void PrintHello(string playerName)
{
    Debug.Log("-----------------");
    Debug.Log($"안녕하세요 {playerName}님!");
    Debug.Log("-----------------");
    Debug.Log($"저는 {playerName}님을 도와드릴 NPC 라고 해요.");
    Debug.Log("-----------------");
    return;
}

PrintHello(player1Name);
PrintHello(player2Name);
PrintHello(player3Name);
```

돌려줄 결과가 없으면 출력 타입에 `void`\
void 함수의 `return;`은 값 없이 함수를 끝낸다는 뜻이라 마지막 줄에서는 생략해도 됨

주석에는 “입력: X”라고 적혀 있는데 최종 코드는 `string playerName`을 받음\
처음엔 고정 문구로 만들었다가 이름을 넣도록 바꾼 흐름으로 보임\
입력만 바꿔서 같은 양식을 세 명에게 재사용함

### 문자열 보간 `$"..."`

```csharp
Debug.Log($"안녕하세요 {playerName}님!");
Debug.Log("안녕하세요 " + playerName + "님!"); // 같은 결과
```

문자열 앞에 `$`를 붙이면 `{}` 안에 변수를 바로 넣을 수 있음\
지금까지는 `+`로 이어 붙였는데 문장 중간에 변수가 들어갈 때는 `$`쪽이 읽기 편해 보임. [Microsoft 문자열 보간 설명](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/tokens/interpolated)

### 레벨 올리기 AddLevel과 예외처리

```csharp
int AddLevel(int currentLevel)
{
    // 예외처리: currentLevel이 음수라면 더하기 1을 하지 않도록
    if (currentLevel <= 0)
    {
        Debug.Log("레벨 문제 있음!");
        return -999;
    }
    return currentLevel + 1;
}
```

currentLevel이 음수면 원하지 않는 동작을 할 수 있음\
그래서 이상한 값이 들어오면 +1을 하지 않고 바로 return으로 함수를 끝냄\
return을 만나면 그 아래 코드는 실행되지 않음

```csharp
int currentLevel = -1;
int nextLevel = AddLevel(currentLevel); // 레벨 문제 있음!
if (nextLevel != -999)
{
    currentLevel = nextLevel;
    Debug.Log(currentLevel);
}
```

| currentLevel | AddLevel 결과 | Console |
| ---: | ---: | --- |
| -1 | -999 | `레벨 문제 있음!`만 출력 |
| 1 | 2 | `2` |

-999는 실제 레벨로는 나올 수 없는 값이라 “문제가 있었다”는 신호로 씀\
부르는 쪽에서 -999인지 확인하고 아니면 레벨을 바꿈

조건이 `<= 0`이라 주석의 “음수”뿐 아니라 0레벨도 막힘\
레벨이 1부터 시작한다고 보면 맞는 범위인 듯

### 함수를 만들면 좋은 점

1. 로직을 재사용하기 좋음
2. 로직 수정이 쉬움 (관리 포인트가 줄어듦)
3. 함수 이름만 보고 동작을 유추해서 쓸 수 있음 (내부 동작은 몰라도 됨)

어제 반복문 앞에서 같은 코드를 5번 적었을 때 문제랑 비슷함\
반복문은 **같은 자리에서** 되풀이하는 것, 함수는 **여러 곳에서** 같은 기능을 불러 쓰는 것

## Chapter 05. 성적 처리기를 함수로 나누기

### Start에는 흐름만

```csharp
int score = 100;
char grade = ' ';

if (score >= 0 && score <= 100)
{
    // 1. 등급 계산을 함수에 맡기고, 결과를 받음
    grade = GetGradeFromScore(score);

    // 2. 4의 배수 판별을 함수에 맡기고, 결과를 받음
    bool isMultiplesOf4 = IsMultipleOf4(score);

    // 3. 받은 결과를 출력
    PrintResult(score, grade, isMultiplesOf4);
}
else
{
    Debug.Log("점수 범위 문제 있음!");
}
```

Chapter 01 풀이에서 if 안에 다 들어 있던 걸 기능 3개로 나눔\
Start만 읽어도 “등급 계산 → 4의 배수 판별 → 출력” 순서가 바로 보임

### 나눈 함수 3개

```csharp
char GetGradeFromScore(int score)
{
    if (score < 0 || score > 100)
    {
        return ' ';
    }
    char result = ' ';
    if (score > 95) { result = 'A'; }
    else if (score > 90) { result = 'B'; }
    else if (score > 85) { result = 'C'; }
    else if (score > 80) { result = 'D'; }
    else { result = 'F'; }

    return result;
}

bool IsMultipleOf4(int score)
{
    if (score < 0 || score > 100)
    {
        return false;
    }
    bool result = (score % 4 == 0);
    return result;
}

void PrintResult(int score, char grade, bool isMultiplesOf4)
{
    Debug.Log("점수: " + score + "점, 학점: " + grade);

    if (isMultiplesOf4)
    {
        Debug.Log(score + "는 4의 배수입니다.");
    }
    else
    {
        Debug.Log(score + "는 4의 배수가 아닙니다.");
    }
}
```

| 함수 | 입력 | 출력 타입 | 하는 일 |
| --- | --- | --- | --- |
| `GetGradeFromScore` | `int` | `char` | 점수 → 학점 |
| `IsMultipleOf4` | `int` | `bool` | 4의 배수인가 |
| `PrintResult` | `int`, `char`, `bool` | `void` | 결과 출력 |

입력은 여러 개 받을 수 있고 출력 타입은 함수마다 다름\
PrintResult처럼 결과를 돌려주지 않고 출력만 하는 함수는 void

### 범위 검사를 두 번 하는 이유

Start에서 이미 0~100점만 들여보내는데 함수 안에서도 다시 범위를 검사함\
함수는 다른 곳에서 따로 불릴 수도 있으니 함수 혼자서도 이상한 값을 막게 해 둔 걸로 보임\
AddLevel의 예외처리와 같은 생각

### 결과 확인

함수 부분만 떼서 별도의 C# 실행(.NET 9.0)으로 경계 점수를 넣어 봄

| 점수 | GetGradeFromScore | IsMultipleOf4 |
| ---: | --- | --- |
| 100 | A | True |
| 96 | A | True |
| 95 | B | False |
| 91 | B | False |
| 90 | C | False |
| 85 | D | False |
| 81 | D | False |
| 80 | F | True |
| 0 | F | True |

어제 switch 풀이로 확인한 표와 결과가 같음\
수업 파일은 score가 100이라 `점수: 100점, 학점: A` → `100는 4의 배수입니다.`가 출력되는 코드

## 오늘 정리

| 주제 | 기억할 내용 |
| --- | --- |
| 범위 밖 값 | 계산 전에 바깥 if로 먼저 막기 |
| bool 대입 | `x = (조건식);` 한 줄로 충분 |
| 2중 반복문 | 바깥 1번에 안쪽 전체, 출력 수는 곱 |
| 안쪽 변수 | 바깥 i가 살아 있어서 j로 따로 선언 |
| 별 피라미드 | 안쪽 조건을 `j <= i`로 바깥에 연결 |
| 지뢰찾기 | 다 찾으면 `break`로 멈추기 |
| 함수 | 입력·행동·출력·이름·출력 타입 |
| return | 결과를 내보내고 함수를 끝냄 |
| void | 돌려줄 결과가 없는 함수 |
| `$"{}"` | 문자열 안에 변수 바로 넣기 |
| 예외처리 | 이상한 입력이면 일찍 return, 특별한 값으로 알림 |

어제는 무엇을 실행할지 고르고 몇 번 되풀이할지 정하는 것까지였음\
오늘은 그 코드를 **이름 붙인 기능 단위로 묶는 것**까지 이어짐

성적 처리기를 if로 한 번, switch로 한 번, 함수로 한 번 본 셈\
같은 문제라도 Start에 다 적을 때보다 함수로 나눴을 때 무엇을 하는 코드인지 훨씬 빨리 읽힘\
기능을 먼저 1, 2, 3으로 나누고 → 그 번호가 그대로 함수가 되는 흐름이 첫날부터 말한 “원하는 동작을 먼저 나누고 코드로 옮기기”랑 이어져 보임
