어제는 변수·자료형부터 산술·대입·비교 연산자까지 봤음\
오늘은 남은 증감 연산자와 논리 연산자를 마무리하고 조건문(`if`, `switch`), 반복문(`for`, `while`)까지 넘어감

비교 연산자로 bool을 만들고 → 논리 연산자로 조건을 묶고 → 조건문으로 실행할 코드를 고르고 → 반복문으로 조건이 맞는 동안 되풀이하는 흐름\
`Operator.cs` 뒷부분과 새로 만든 `Condition.cs`, `Loop.cs`의 예제를 같이 정리해 봄

## Chapter 01. 증감 연산자 `++`, `--`

### 1 더하는 방법이 세 가지

```csharp
int aa = 0;

aa = aa + 1; // 1
aa += 1;     // 2
aa++;        // 3
```

세 줄 모두 aa를 1씩 늘리는 코드\
`++`는 1 증가, `--`는 1 감소시키는 연산자임

### 후증가와 선증가는 돌려주는 값이 다름

```csharp
int a1 = 0;
Debug.Log(a1++); // 0
Debug.Log(a1++); // 1
Debug.Log(a1);   // 2

int a2 = 0;
Debug.Log(++a2); // 1
Debug.Log(++a2); // 2
Debug.Log(a2);   // 2
```

| 형태 | 이름 | 식의 결과 | 변수 값 |
| --- | --- | --- | --- |
| `a1++` | 후증가 | 증가하기 **전** 값 | 1 증가 |
| `++a2` | 선증가 | 증가한 **후** 값 | 1 증가 |

둘 다 결국 변수는 1 늘어남\
차이는 그 식을 `Debug.Log()` 같은 곳에 넣었을 때 어떤 값이 쓰이느냐임

수업에서는 “1 더하는 타이밍이 실행 후 / 실행 전”으로 설명함\
나는 **식이 돌려주는 값이 증가 전 값인지 후 값인지**로 기억하는 게 덜 헷갈림. [Microsoft 증가 연산자 설명](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/operators/arithmetic-operators#increment-operator-)

### 한 줄에 섞어 쓰면?

```csharp
int b1 = 0;
Debug.Log(++b1 + b1++ + ++b1 + b1++); // 8
Debug.Log(b1);                        // 4
```

왼쪽부터 하나씩 풀어 보면

| 순서 | 식 | 식의 결과 | 실행 후 b1 |
| --- | --- | ---: | ---: |
| 1 | `++b1` | 1 | 1 |
| 2 | `b1++` | 1 | 2 |
| 3 | `++b1` | 3 | 3 |
| 4 | `b1++` | 3 | 4 |

더하는 값은 `1 + 1 + 3 + 3 = 8`\
`++`가 네 번 실행됐으니 마지막 b1은 4

이런 식은 문제 풀이용으로는 재밌지만 실제 코드에서는 읽기 어려움\
증가는 따로 한 줄로 빼서 쓰는 게 나을 듯

### 선증가가 후증가보다 성능이 좋음

수업 중에 선증가가 후증가보다 성능이 좋다는 이야기가 나옴\
후증가는 증가 전 값을 따로 돌려줘야 하니까 그만큼 할 일이 하나 더 있는 셈

그래도 둘 중 고를 때는 먼저 **식의 결과로 증가 전 값이 필요한지 후 값이 필요한지** 보기\
결과가 달라지는 문제라 의미부터 맞추고 그다음에 성능 생각하기

### 클래스 안 변수와 Update

```csharp
public int aa = 0;

void Update()
{
    aa++;
    Debug.Log(aa);
}
```

수업 파일에서는 클래스 안, 함수 밖에 선언한 aa를 전역 변수라고 적어 둠\
C#에서는 이런 변수를 **필드(멤버 변수)**라고 부름

Start 안의 지역변수는 Start가 끝나면 사라지지만 필드는 컴포넌트가 살아 있는 동안 값을 유지함\
그래서 Update에서 `aa++`를 하면 매 프레임 1씩 늘어남\
`public`이라 Inspector에서도 값을 확인할 수 있음

## Chapter 02. 논리 연산자 `&&`, `||`, `!`

### bool끼리 묶는 연산자

| 연산자 | 이름 | 결과가 true인 경우 |
| --- | --- | --- |
| `A && B` | AND | A와 B가 **둘 다** true |
| A OR B | OR | A나 B 중 **하나라도** true |
| `!A` | NOT | A가 false일 때 (결과 반전) |

OR는 코드에서 `A || B`로 적음\
비교 연산자가 만든 bool을 다시 묶어서 더 큰 조건을 만드는 것

### AND: 레벨 제한과 가격을 둘 다 만족해야 구매

```csharp
int myLevel = 50;
int myWallet = 100000;
int itemRequiredLevel = 50;
int itemPrice = 10000;

bool A = myLevel >= itemRequiredLevel; // true
bool B = myWallet >= itemPrice;        // true

bool canBuy = A && B;
Debug.Log("canBuy? : " + canBuy); // canBuy? : True
```

레벨이 49였다면 A가 false라서 돈이 많아도 canBuy는 false\
조건이 **모두** 맞아야 하는 상황에 &&

### OR: 골드나 루비 중 하나로 구매

```csharp
int myGold = 10000;
int myRuby = 100;
int itemGoldPrice = 5000;
int itemRubyPrice = 50;

bool A1 = myGold >= itemGoldPrice; // true
bool B1 = myRuby >= itemRubyPrice; // true

bool canBuy1 = A1 || B1;
Debug.Log("canBuy1 : " + canBuy1); // canBuy1 : True
```

인게임 재화와 유료 재화 중 **하나만** 충분해도 살 수 있는 상황\
여기서는 둘 다 true지만 골드가 부족해도 루비가 있으면 true

### 조건을 bool 변수로 먼저 나누기

수업 예제는 조건을 바로 `&&`로 잇지 않고 A, B에 먼저 담음\
“레벨 조건 → 가격 조건 → 둘 다 맞는가”로 나눠 적으니 읽기 쉬움

어제 정리한 것처럼 원하는 동작을 먼저 나누고 코드로 옮기는 흐름과 같음\
나중에는 `canBuy`처럼 의미가 보이는 이름을 붙이는 게 중요해 보임

### NOT과 괄호

```csharp
bool someBool = (100 > 200);
Debug.Log("SomeBool : " + someBool);   // SomeBool : False
Debug.Log("!SomeBool : " + !someBool); // !SomeBool : True
```

`!`는 bool 결과를 뒤집음

```csharp
bool Aa = false;
bool Bb = false;

Debug.Log(!Aa && Bb);   // False
Debug.Log(!(Aa && Bb)); // True
```

| 식 | 계산 순서 | 결과 |
| --- | --- | --- |
| `!Aa && Bb` | `(!false) && false` → `true && false` | False |
| `!(Aa && Bb)` | `!(false && false)` → `!false` | True |

`!`는 `&&`보다 먼저 계산됨\
그래서 괄호가 없으면 Aa만 뒤집히고, 괄호로 묶어야 전체 결과가 뒤집힘\
같은 기호를 써도 괄호 위치에 따라 의미가 완전히 달라짐

참고로 우선순위는 `!` → `&&` → `||` 순서\
섞어 쓸 때는 헷갈리지 않게 괄호를 적는 편이 안전할 듯. [Microsoft 논리 연산자 설명](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/operators/boolean-logical-operators)

### 수업 외로 찾아본 것: 단락 평가

`&&`는 왼쪽이 false면 오른쪽을 계산하지 않음\
`||`는 왼쪽이 true면 오른쪽을 계산하지 않음\
결과가 이미 정해졌기 때문

오른쪽에 함수 호출이나 값 변경이 있으면 실행 여부가 달라질 수 있어서 기억해 두기\
`&`, `|`를 bool에 쓰면 양쪽을 다 계산한다고 함

## Chapter 03. 조건문 `if`

### 조건에 따라 다른 행동을 하게 만들기

조건문은 조건의 참·거짓에 따라 실행할 코드를 고르는 문법임

```csharp
if (조건)
{
    // 조건이 true일 때 실행
}
```

수업 예제 상황\
지갑에 1000원 → 자전거는 500원 → 탈 수 있으면 자전거, 없으면 걸어감

### if → else if → else

```csharp
int wallet = 1000;
int bikePrice = 500;
int busPrice = 300;

if (wallet >= bikePrice)
{
    Debug.Log("자전거 탐");
}
else if (wallet >= busPrice)
{
    Debug.Log("버스 탐");
}
else
{
    Debug.Log("걸어감");
}
// 자전거 탐
```

| 문법 | 역할 |
| --- | --- |
| `if` | 첫 번째 조건 검사 |
| `else if` | 앞 조건이 false일 때 다음 조건 검사 |
| `else` | 위 조건이 전부 false일 때 실행 |

wallet이 1000이라 첫 조건부터 true → “자전거 탐”만 출력됨\
버스 조건은 검사하지 않고 넘어감

### if-else로 짝수·홀수 구분

```csharp
int someNumber = 2;

if (someNumber % 2 == 0)
{
    Debug.Log("someNumber는 짝수입니다.");
}
else
{
    Debug.Log("someNumber는 홀수입니다.");
}
// someNumber는 짝수입니다.
```

어제 배운 `%`를 조건에 그대로 씀\
“짝수인가?”를 → “2로 나눈 나머지가 0인가?”로 바꿔서 생각하는 게 포인트\
결과가 둘 중 하나라 else 하나면 충분함

### 위에서부터 검사하니 순서가 중요

```csharp
int wallet1 = 10000;
int taxiPrice = 5000;
int subwayPrice = 2000;
int ridePrice = 1000;

if (wallet1 >= taxiPrice)
{
    Debug.Log("택시 탈꺼얌~");
}
else if (wallet1 >= subwayPrice)
{
    Debug.Log("지하철 탈꺼얌~");
}
else if (wallet1 >= ridePrice)
{
    Debug.Log("자전거 탈꺼얌~");
}
else
{
    Debug.Log("걸어갈꺼얌~");
}
// 택시 탈꺼얌~
```

10000원이면 지하철·자전거 조건도 true지만 택시 하나만 출력됨\
else if 묶음은 위에서부터 검사하다가 **처음 true인 곳 하나만** 실행하기 때문

그래서 비싼 것부터 적어야 의도대로 동작함\
만약 `wallet1 >= ridePrice`를 맨 위에 두면 돈이 많아도 항상 자전거만 타게 됨

조건은 다르지만 **동시에 일어나면 안 되는 선택지**를 고를 때 사용

### if를 여러 개 쓰면 전부 검사함

```csharp
int wallet2 = 10000;
int fantaPrice = 5000;
int cokePrice = 3000;
int mirandaPrice = 2500;

if (wallet2 >= fantaPrice)
{
    Debug.Log("환타 마실꺼얌~");
    wallet2 -= fantaPrice;
}
if (wallet2 >= cokePrice)
{
    Debug.Log("콜라 마실꺼얌~");
    wallet2 -= cokePrice;
}
if (wallet2 >= mirandaPrice)
{
    Debug.Log("미란다 마실꺼얌~");
    wallet2 -= mirandaPrice;
}
// 환타 마실꺼얌~
// 콜라 마실꺼얌~
```

이번엔 else 없이 if만 세 개\
if는 만나는 대로 전부 조건을 검사해서 여러 개가 실행될 수 있음

값을 따라가 보면

| 검사 | 조건 | 결과 | 남은 돈 |
| --- | --- | --- | ---: |
| 환타 | 10000 >= 5000 | 마심 | 5000 |
| 콜라 | 5000 >= 3000 | 마심 | 2000 |
| 미란다 | 2000 >= 2500 | 안 마심 | 2000 |

각 if 안에서 돈을 빼기 때문에 다음 조건은 줄어든 돈으로 검사함\
미란다는 앞에서 돈을 다 써서 못 마심

| 구조 | 검사 방식 | 쓰는 상황 |
| --- | --- | --- |
| if 여러 개 | 전부 각각 검사 | 여러 개가 동시에 일어나도 되는 일 |
| if - else if - else | 처음 true에서 멈춤 | 하나만 골라야 하는 일 |

### 중괄호 안에 if 넣기

```csharp
if (true)
{
    if (false)
    {

    }
    else if (true) { }
    else if (true) { }
}
```

if 블록 안에 다시 if를 넣을 수도 있고 else if는 필요한 만큼 이어 붙일 수 있음\
구조를 보여 주는 예시라 실제로 의미 있는 조건은 아님

## Chapter 04. Visual Studio 디버깅 단축키

교통수단 예제에서 브레이크포인트를 걸고 한 줄씩 실행해 봄\
어떤 if로 들어가는지 눈으로 따라갈 수 있음

| 단축키 | 동작 |
| --- | --- |
| `F9` | 현재 줄에 브레이크포인트 걸기·해제 |
| `F5` | 디버그 시작 / 디버깅 중이면 다음 브레이크포인트까지 계속 실행 |
| `F10` | 다음 줄로 한 줄씩 이동 |
| `Shift + F5` | 디버깅 종료 |

브레이크포인트는 디버깅을 위해 실행을 멈추고, 개발자가 재개하면 이어서 실행함\
멈춰 있는 동안 변수 값을 확인할 수 있어서 Debug.Log를 여러 번 찍는 것보다 흐름 보기가 편함

수업 중 코루틴과도 비교해 봄\
코루틴은 `yield` 지점에서 그 코루틴만 기다리고 다른 게임 로직은 계속 실행됨\
브레이크포인트는 게임 실행 자체가 멈춘다는 점이 다름

## Chapter 05. switch ~ case

### else if로 레벨마다 나누면

```csharp
int myLevel = 4;

if (myLevel == 1)
{
    Debug.Log("축하합니다! 용사님의 레벨은 " + myLevel + "입니다.");
}
else if (myLevel == 2)
{
    Debug.Log("축하합니다! 용사님의 레벨은 " + myLevel + "입니다.");
}
else if (myLevel == 3)
{
    Debug.Log("축하합니다! 용사님의 레벨은 " + myLevel + "입니다.");
}
else if (myLevel == 4)
{
    Debug.Log("축하합니다! 게임을 클리어 하였습니다.");
}
```

만렙이 4인 게임에서 레벨이 오를 때마다 축하 문구를 띄우는 예제\
myLevel이 4라 “게임을 클리어 하였습니다.”가 출력됨

레벨처럼 하나의 값이 1, 2, 3…으로 정해진 경우를 나누는데 `myLevel ==` 비교가 계속 반복됨\
이렇게 순서대로 늘어나는 값으로 나눌 때 쓰는 게 `switch ~ case`

### switch로 바꾸기

```csharp
switch (myLevel)
{
    case 1: // myLevel 이 1일 때
        Debug.Log("축하합니다! 용사님의 레벨은 " + myLevel + "입니다.");
        break;
    case 2: // myLevel 이 2일 때
        Debug.Log("축하합니다! 용사님의 레벨은 " + myLevel + "입니다.");
        break;
    case 3: // myLevel 이 3일 때
        Debug.Log("축하합니다! 용사님의 레벨은 " + myLevel + "입니다.");
        break;
    case 4: // myLevel 이 4일 때
        Debug.Log("축하합니다! 게임을 클리어 하였습니다.");
        break;
}
// 축하합니다! 게임을 클리어 하였습니다.
```

| 부분 | 의미 |
| --- | --- |
| `switch (myLevel)` | 검사할 변수 |
| `case 4:` | 변수 값이 4일 때 여기부터 실행 |
| `break;` | 해당 case 실행을 끝내고 switch 밖으로 나감 |

변수 이름을 한 번만 적고 값별로 case를 나누니까 else if보다 한눈에 들어옴\
수업에서는 switch에 넣는 변수로 int, char, enum 등을 예로 듦\
`0, 1, 2, 3`이나 `'a'`의 97, 98, 99처럼 정해진 값으로 딱 떨어지는 경우에 잘 맞음

C#에서는 case 안에 실행할 코드가 있으면 `break` 같은 끝맺음이 필요함\
빼먹으면 다음 case로 넘어가지 않고 컴파일 오류가 남\
범위 비교(`>=`)가 필요한 교통수단 예제 같은 건 if - else if가 더 자연스러워 보임. [Microsoft switch 설명](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/statements/selection-statements#the-switch-statement)

### 같은 코드를 실행하는 case는 묶을 수 있음

1~3레벨은 출력 문구가 똑같음\
이럴 때는 case를 붙여 써서 줄일 수 있음

```csharp
switch (myLevel)
{
    case 1:
    case 2:
    case 3:
        Debug.Log("축하합니다! 용사님의 레벨은 " + myLevel + "입니다.");
        break;
    case 4:
        Debug.Log("축하합니다! 게임을 클리어 하였습니다.");
        break;
}
```

`case 1:`, `case 2:`, `case 3:`는 코드 묶음 하나에 붙은 이름표 3개라고 보면 됨\
값이 맞는 이름표로 바로 가서 그 아래 코드를 break까지 실행함

처음엔 “break를 만나기 전까지 계속 조건 검사를 한다”로 적어 뒀는데\
조건을 하나씩 검사하며 내려가는 게 아니라 **맞는 case로 바로 들어가는 것**으로 이해하는 게 맞음\
case 사이에 코드가 하나도 없을 때만 이렇게 묶을 수 있음

위아래 switch 결과는 같음\
코드에 둘 다 남겨 두면 myLevel이 4일 때 클리어 문구가 Console에 두 번 찍힘

### if로도 다 되는데 switch를 쓰는 이유

switch를 몰라도 if만으로 모든 조건을 표현할 수 있음\
그런데 레벨처럼 순차적으로 늘어나는 값은 if로 쓰면 `myLevel ==`가 계속 반복돼서 읽기 불편함\
이럴 때 switch로 가독성을 올리는 것

switch 안에 switch나 if를 넣을 수도 있고, if 안에 switch를 넣을 수도 있음\
섞어 쓸 수 있으니 상황에 맞게 고르기

## Chapter 06. 과제 1 성적 처리기

```text
점수는 0~100점
100포함 ~ 95초과: A
95포함 ~ 90초과: B
90포함 ~ 85초과: C
85포함 ~ 80초과: D
그 외 점수: F
받은 점수가 4의 배수인지도 확인

출력 예시
점수: 95점, 학점: B, 4의 배수가 아닙니다.
```

### 처음 짠 코드에서 막힌 부분

처음에는 학점을 매기는 switch의 `default` 안, `break` 뒤에 출력 if를 넣었음\
break에서 switch를 빠져나가니까 그 아래 코드는 실행되지 않음\
학점은 switch에서 정하고 → 출력은 switch가 끝난 뒤에 한 번만 하도록 옮김

그다음엔 case에 범위를 바로 적는 방식으로 짰음

```csharp
int score = 95;
string grade;

switch (score)
{
    case > 95 and <= 100:
        grade = "A";
        break;
    // B, C, D 생략
    case < 80 and >= 0:
        grade = "F";
        break;
}

Debug.Log("점수: " + score + "점, 학점: " + grade + ...);
// error CS0165: 할당되지 않은 'grade' 지역 변수를 사용했습니다.
```

`string grade;`는 선언만 하고 값을 안 넣은 상태\
case가 모든 점수를 덮지 못하면 grade가 빈 채로 쓰일 수 있어서 컴파일러가 막음

실제로 빠진 값도 있었음\
`< 80`이라 **80점**이 어느 case에도 안 걸림\
기준상 D는 “85포함 ~ 80초과”라 80점은 F여야 함

그리고 `and`는 수업에서 안 나온 문법이라 배운 것만으로 다시 짜 보기로 함

### 방법 1. if - else if

```csharp
if (score > 95)
{
    grade = "A";
}
else if (score > 90)
{
    grade = "B";
}
else if (score > 85)
{
    grade = "C";
}
else if (score > 80)
{
    grade = "D";
}
else
{
    grade = "F";
}
```

오늘 배운 “위에서부터 검사, 처음 true 하나만 실행”을 그대로 씀\
`else if (score > 90)`까지 내려왔다면 이미 95 이하라는 뜻이라 위쪽 범위를 다시 안 적어도 됨

범위를 전부 적고 싶으면 `&&`를 사용

```csharp
if (score > 95 && score <= 100)
{
    grade = "A";
}
else if (score > 90 && score <= 95)
{
    grade = "B";
}
// C, D도 같은 식
else
{
    grade = "F";
}
```

| | 아래 범위만 적기 | 범위 전부 적기 |
| --- | --- | --- |
| 조건 | `score > 90` | `score > 90 && score <= 95` |
| 순서 | 바꾸면 결과가 달라짐 | 바꿔도 결과가 같음 |
| 장점 | 짧음 | 조건만 봐도 범위가 보임 |

F는 범위를 다 적더라도 else로 끝내기\
`else if (score >= 0 && score <= 80)`으로 쓰면 어디에도 안 걸리는 값이 생겨서 같은 CS0165 오류가 다시 남

### 방법 2. 나눗셈으로 구간 번호 만들기

switch의 case에는 범위가 아니라 정해진 값을 적어야 함\
그래서 어제 배운 **정수 나눗셈**으로 점수를 5점 단위 구간 번호로 바꿈

```csharp
switch ((score - 1) / 5)
{
    case 19: // 96 ~ 100
        grade = "A";
        break;
    case 18: // 91 ~ 95
        grade = "B";
        break;
    case 17: // 86 ~ 90
        grade = "C";
        break;
    case 16: // 81 ~ 85
        grade = "D";
        break;
}
```

처음엔 `- 1`을 하면 점수에 오차가 생기는 거 아닌가 싶었음\
그런데 이 식은 case를 고를 때만 쓰고 score에 다시 저장하지 않음\
score는 계속 95로 남아 있고 출력할 때도 95점으로 나옴

전부 int라서 소수 오차도 없음\
정수 나눗셈은 소수 부분을 그냥 버림

```text
(95 - 1) / 5 = 94 / 5 = 18.8 → 소수 버림 → 18 → B
```

`- 1`은 구간 경계를 맞추려고 넣는 것

| 점수 | score / 5 | (score - 1) / 5 | 기준상 학점 |
| --- | ---: | ---: | --- |
| 100 | 20 | 19 | A |
| 96 | 19 | 19 | A |
| 95 | **19** | **18** | B |
| 91 | 18 | 18 | B |
| 90 | **18** | **17** | C |
| 81 | 16 | 16 | D |
| 80 | **16** | **15** | F |

`score / 5`로만 나누면 95와 96이 같은 구간이 돼서 95점이 A가 됨\
기준은 “95포함 ~ 90초과”라 경계가 95와 96 사이에 있어야 함\
1을 빼면 구간이 96~100, 91~95, 86~90처럼 한 칸씩 밀려서 기준과 맞음

### default 대신 F로 초기화

| 선언 | default 필요? |
| --- | --- |
| `string grade;` | 필요. 없으면 CS0165 |
| `string grade = "F";` | 없어도 됨. 어느 case에도 안 걸리면 F가 남음 |

처음부터 F를 넣어 두면 case 16~19에 안 걸리는 점수는 그대로 F\
F를 default로 처리할지 초기값으로 처리할지 한 곳만 정하면 됨

if로 81~100점만 감싸고 else로 F를 빼는 것도 생각해 봤는데\
F로 초기화했으면 else는 필요 없음\
if는 “81~100점만 switch로 나눈다”는 의도를 보여 주는 정도의 의미

### case를 if 안에 넣을 수는 없음

```csharp
switch ((score - 1) / 5)
{
    if (score > 80 && score <= 100) // 컴파일 안 됨
    {
        case 19:
        // ...
    }
}
```

switch 중괄호 안에는 `case 값:`으로 시작하는 부분만 올 수 있음\
case를 if 블록 안에 넣을 수도 없음

if와 switch를 같이 쓰려면 한쪽이 다른 쪽을 **통째로** 감싸야 함

### 완성한 코드

```csharp
int score = 95;
string grade = "F";

if (score > 80 && score <= 100)
{
    switch ((score - 1) / 5)
    {
        case 19: // 96 ~ 100
            grade = "A";
            break;
        case 18: // 91 ~ 95
            grade = "B";
            break;
        case 17: // 86 ~ 90
            grade = "C";
            break;
        case 16: // 81 ~ 85
            grade = "D";
            break;
    }
}
if (score % 4 == 0)
{
    Debug.Log("점수: " + score + "점, 학점: " + grade + ", 4의 배수입니다.");
}
else
{
    Debug.Log("점수: " + score + "점, 학점: " + grade + ", 4의 배수가 아닙니다.");
}
// 점수: 95점, 학점: B, 4의 배수가 아닙니다.
```

경계 점수를 넣어서 별도의 C# 실행(.NET 9.0)으로도 확인함

| 점수 | 학점 | 4의 배수 |
| --- | --- | --- |
| 100 | A | O |
| 96 | A | O |
| 95 | B | X |
| 91 | B | X |
| 90 | C | X |
| 85 | D | X |
| 81 | D | X |
| 80 | F | O |
| 0 | F | O |

과제 전제가 0~100점이라 범위 밖 점수는 따로 처리하지 않음\
101점이나 -5점을 넣으면 지금은 F로 나옴

### case 묶기는 여기선 못 씀

case를 묶는 건 **여러 case가 같은 코드를 실행할 때**만 가능\
성적 처리기는 19, 18, 17, 16이 각각 A, B, C, D로 전부 다름

`(score - 1) / 5`로 5점 구간을 숫자 하나로 만든 게 이미 case를 줄인 셈\
나눗셈 없이 `case 100: case 99: … case 96:`처럼 묶으면 case가 20개가 돼서 오히려 길어짐

레벨 1~3은 같은 보상, 월~금은 평일처럼 같은 결과를 공유하는 경우에 쓰면 될 듯

## Chapter 07. 반복문(Loop)

### 같은 코드를 5번 적으면?

레벨을 연속으로 5번 올려 주는 물약을 먹은 상황\
레벨이 오를 때마다 1을 더하고 문구를 띄워야 함

```csharp
int level = 0;

++level;
Debug.Log("플레이어의 레벨이 올랐습니다!, 현재레벨: " + level);
++level;
Debug.Log("플레이어의 레벨이 올랐습니다!, 현재레벨: " + level);
++level;
Debug.Log("플레이어의 레벨이 올랐습니다!, 현재레벨: " + level);
++level;
Debug.Log("플레이어의 레벨이 올랐습니다!, 현재레벨: " + level);
++level;
Debug.Log("플레이어의 레벨이 올랐습니다!, 현재레벨: " + level);
```

동작은 하지만 문제가 많음

- 코드가 길어져서 보기 힘듦
- 몇 번 반복했는지 한눈에 안 보임
- 횟수가 100번, 1000번이 되면 감당이 안 됨
- 문구를 바꾸려면 반복한 횟수만큼 고쳐야 함 → 관리 포인트가 늘어남

### for문

```csharp
for (변수 선언; 반복 조건; 변수 증감)
{
    // 반복하는 동안 수행할 행동
}
```

```csharp
for (int i = 0; i < 5; ++i)
{
    ++level;
    Debug.Log("플레이어의 레벨이 올랐습니다!, 현재레벨: " + level);
}
```

| 부분 | 의미 |
| --- | --- |
| `int i = 0` | 반복 횟수를 셀 변수, 처음 한 번만 실행 |
| `i < 5` | 매번 반복하기 전에 검사, true면 실행 |
| `++i` | 한 번 반복이 끝날 때마다 실행 |

i가 0, 1, 2, 3, 4일 때 실행되고 5가 되면 조건이 false라 끝남 → 5번 반복\
5번 쓰던 코드가 한 번으로 줄고 횟수는 `5`만 바꾸면 됨

수업 파일에서는 위에서 직접 5번 올린 level을 그대로 이어 써서 for에서는 6~10이 출력됨

증감 부분에 오전에 배운 `++i`가 그대로 나옴\
여기서는 `i++`로 적어도 결과는 같음\
증감식의 결과 값을 따로 쓰지 않기 때문

### 시작값과 증가량 바꾸기

```csharp
for (int i = 2; i <= 12; i += 2)
{
    Debug.Log(i);
}
// 2, 4, 6, 8, 10, 12
```

2부터 시작해서 2씩 늘리고 12 이하일 때까지 반복\
증감 부분에 `++i`만 쓰는 게 아니라 `i += 2`처럼 복합 대입도 쓸 수 있음\
`<`와 `<=` 차이로 마지막 값이 포함되는지가 달라지니 조건을 잘 보기

### continue: 이번 반복만 건너뛰기

```csharp
for (int i = 0; i < 5; ++i)
{
    if (i == 2)
    {
        continue;
    }
    Debug.Log(i);
}
// 0, 1, 3, 4
```

i가 2일 때 continue를 만나면 아래 Debug.Log를 건너뛰고 다음 반복(`++i`)으로 넘어감\
반복 자체는 끝나지 않아서 3, 4는 출력됨

### break: 반복 전체를 끝내기

```csharp
for (int i = 0; i < 5; ++i)
{
    if (i == 2)
    {
        break;
    }
    Debug.Log(i);
}
// 0, 1
```

i가 2일 때 break를 만나면 반복문을 완전히 빠져나감\
그래서 0, 1만 출력됨

| 키워드 | 동작 | 결과 |
| --- | --- | --- |
| `continue` | 이번 반복만 건너뛰고 다음 반복으로 | 0, 1, 3, 4 |
| `break` | 반복문을 바로 끝냄 | 0, 1 |

switch에서 쓴 break도 “지금 블록에서 빠져나간다”는 점에서 같은 느낌으로 보임

### while문

```csharp
while (반복 조건)
{
    // 반복하는 동안 수행할 내용
}
```

“플레이어가 도착 지점에 도착하기 전까지 반복”처럼 **몇 번 반복할지 미리 모르는 경우**\
수업에서는 이런 요구사항은 for로는 구현이 안 되고 while로 구현한다고 설명함

```text
while (플레이어의 위치 != 목적지의 위치)
```

정확히는 for도 `for (; 조건; )`처럼 조건만 남기면 비슷하게 쓸 수는 있음\
그래도 횟수가 정해진 반복은 for, 조건이 맞는 동안 계속하는 반복은 while로 나누는 게 읽기 편할 듯

```csharp
int ii = 0;

while (ii <= 10)
{
    Debug.Log(ii);
    ++ii;
}
// 0, 1, 2, … , 10
```

목표 수치는 10이지만 조건이 `ii <= 10`이라 0부터 10까지 **11번** 출력됨\
반복이 끝난 뒤 ii는 11

for는 증감을 괄호 안에 적지만 while은 블록 안에서 직접 `++ii`를 해 줘야 함\
이걸 빼먹으면 ii가 계속 0이라 조건이 영원히 true → 무한 반복\
Start 안에서 무한 반복이 돌면 그 프레임이 끝나지 않아 Unity 에디터가 멈출 수 있으니 조건이 언젠가 false가 되는지 꼭 확인하기

| | for | while |
| --- | --- | --- |
| 주로 쓰는 경우 | 반복 횟수가 정해짐 | 조건이 맞는 동안 계속 |
| 변수 증감 | 괄호 안에 적음 | 블록 안에서 직접 |
| 예시 | 레벨 5번 올리기 | 목적지에 도착할 때까지 이동 |

## 오늘 정리

| 주제 | 기억할 내용 |
| --- | --- |
| 증감 | `a++`는 증가 전 값, `++a`는 증가 후 값을 돌려줌 |
| AND | 조건이 모두 true일 때 true |
| OR | 조건 중 하나라도 true면 true |
| NOT | 결과 반전, AND·OR보다 먼저 계산 |
| if - else if - else | 위에서부터 검사, 처음 true 하나만 실행 |
| if 여러 개 | 각각 전부 검사, 여러 개 실행 가능 |
| switch | 한 변수의 값별로 case를 나눔, case 끝에 break |
| case 묶기 | 같은 코드를 실행하는 case만 붙여 쓸 수 있음 |
| 변수 초기화 | 값을 안 넣고 선언하면 모든 경로에서 대입해야 함 (CS0165) |
| for | 횟수가 정해진 반복, 선언·조건·증감을 한 줄에 |
| continue / break | 이번 반복만 건너뛰기 / 반복 전체 끝내기 |
| while | 조건이 true인 동안 반복, 증감을 빼먹으면 무한 반복 |
| 디버깅 | F9 브레이크포인트, F10 한 줄씩, F5 계속, Shift+F5 종료 |

어제는 값을 저장하고 계산하고 비교하는 것까지였음\
오늘은 그 비교 결과로 **무엇을 실행할지 고르고, 몇 번 되풀이할지 정하는 것**까지 이어짐

조건문은 문법보다 조건을 어떻게 나누느냐가 더 어려운 듯\
“하나만 골라야 하나, 여러 개가 같이 일어나도 되나”를 먼저 정하고\
그다음 if 여러 개인지 else if 묶음인지, 값별로 나누는 switch인지 고르기

과제에서는 범위로 나누는 문제를 switch로 풀려다 보니 돌아가는 길이 많았음\
범위는 if, 딱 떨어지는 값은 switch라는 기준을 직접 부딪혀 보면서 이해함
